# PMP isolation of U-mode steps in the L3 RISC-V model: design

This directory proves, about the HOL4 RISC-V model alone (`riscvTheory`, generated by L3 from
`../src/riscv.spec`), that a machine step taken in U-mode respects the PMP configuration. It is
item 9 of HolBA's `S3K_VERIFICATION_PLAN.md`, and is stated so that the S3K work (item 10) can
compose it with the kernel's contracts, but nothing here mentions S3K.

Stage 1 builds the foundation, `riscv_footprintTheory`: what every function on the way from
the step function `Next` to memory reads and writes. Stage 2 proves theorems (a)-(d) of §2 in
`riscv_isolationTheory`, on top of it and of `riscv_pmpTheory` (the PMP check byte by byte and
as a function of the CSR words) and `riscv_framesTheory` (the fields each function never
updates), and checks them on a concrete configuration in `riscv_isolation_exampleTheory`. Both
stages are done; "As proved" at the end of §2 lists where the proved statements differ from
the planned ones above it, and `README.md` states every theorem in words.

Two additions serve a kernel that keeps every PMP entry OFF or NAPOT and takes system calls by
`ecall`: `riscv_pmpTheory` says in which region a byte that U-mode may access lies (§2 (e)),
and `riscv_trapTheory` gives the exact trap state of a U-mode step that runs ECALL and what a
step that takes no interrupt says of the timer (§2 (f)), checked on a concrete state in
`riscv_trap_exampleTheory`. `riscv_trapTheory` is the first theory of the directory with the
step library's `riscv_stepTheory` as an ancestor (I11, I14).

A third addition relates the spec's `Next` to the step function `NextRISCV` of the step
library, with which HolBA lifts programs: `riscv_refineTheory` proves that from ghost-equal
states (equal but for six ghost fields that `NextRISCV` does not maintain) the two steps give
ghost-equal states, when the step takes no interrupt and its instruction reads no counter CSR
(§2 (g)); `riscv_refine_exampleTheory` applies this to step theorems of the step library. Both
have `riscv_stepTheory` as an ancestor (I18).

A fourth addition is about the machine timer, which this model keeps in memory: `mtime` and
`mtimecmp` are doublewords of the CLINT that nothing but an instruction writing memory changes.
`riscv_timerTheory` models the clock of the platform as an environment that writes the bytes of
`mtime` between steps, defines the tick-point execution (the environment may advance the clock
after the steps that a condition selects) and the hardware execution (the clock is set before
every step), gives the exact trap state of the timer interrupt from U-mode, proves that no
interrupt is taken in M-mode with MIE clear whatever the CLINT holds, and that an M-mode step
commutes with a change of bytes that it does not read, CLINT bytes included, from which it
derives the deferral of the clock along steps that read it at most once (§2 (h)).
`riscv_timer_exampleTheory` evaluates the timer trap of a concrete state. Both have
`riscv_stepTheory` as an ancestor (I24).

## 0. Sources and notation

| Ref | Document |
|---|---|
| P | The RISC-V Instruction Set Manual, Volume II: Privileged Architecture, version 20260120 |
| U | Volume I: Unprivileged Architecture (the version cited by `../doc`) |
| DP | `../doc/design-privileged.md` (WP1-WP6): chapter 5 is the PMP, decisions D47-D62 |
| DS | `../doc/design-smode.md` (WP7): chapter 3 is address translation, [S1]-[S3] |

The PMP rules used are P §3.7 (p.70-74): §3.7.1 the CSRs and the `pmpcfg` bits, §3.7.1.1
address matching, §3.7.1.2 locking, §3.7.1.3 "the lowest-numbered PMP entry that matches any
byte of an access determines whether that access succeeds or fails ... the matching PMP entry
must match all bytes of an access, or the access fails" and "if no PMP entry matches an M-mode
access, the access succeeds; if no PMP entry matches an S-mode or U-mode access, but at least
one PMP entry is implemented, the access fails" (p.73), and §3.7.2 (p.74). The model implements
them in `pmpCheck`, `pmpEntryCheck`, `pmpRegion`, `pmpPermits` (DP §5.3-5.4, [D53]): 16
entries ([D47]), grain 0 ([D48]), all four A modes ([D50]), no stored entry with R = 0 and W =
1 ([D49]).

In HOL, `s : riscv_state`; the hart is `s.procID`; memory is `s.MEM8 : word64 -> word8`;
`s with MEM8 := m` is `s` with its memory replaced. `User`, `Supervisor`, `Machine` are the
`Privilege` constructors; `c_privilege` holds `privLevel` of the current one (0w, 1w, 3w).

## 1. Definitions

### 1.1 In `riscv_footprintTheory` (Stage 1, built)

| Name | Definition | Meaning |
|---|---|---|
| `in_range a n x` | `w2n (x - a) < n` | `x` is one of the bytes `a .. a + n - 1` (mod 2^64) |
| `same_except D s1 s2` | `(s2 = s1 with MEM8 := s2.MEM8) /\ !x. ~D x ==> (s1.MEM8 x = s2.MEM8 x)` | the states are equal except for the contents of the bytes in `D` |
| `data_bytes (va, n, kind) s x` | `(w2n va MOD n = 0) /\ ?pa. (dataAddr (va, n, kind) s = TR_Address pa) /\ in_range pa n x` | `x` is a byte of the aligned data access at `va`, at the physical address that `dataAddr` approved |
| `fetch_bytes s x` | `~word_bit 0 (PC s) /\ ((?pa. (fetchAddr (PC s) s = TR_Address pa) /\ in_range pa 2 x) \/ (?pa. (fetchAddr (PC s + 2w) s = TR_Address pa) /\ in_range pa 2 x))` | `x` is a byte of a fetch parcel that `fetchAddr` approved |
| `clint_byte h x` | `in_range (CLINT_BASE + 0xBFF8w) 8 x \/ in_range (CLINT_BASE + 0x4000w + 8w * w2w h) 8 x \/ (x = CLINT_BASE + 4w * w2w h)` | `mtime`, `mtimecmp` of hart `h`, the `msip` byte of hart `h` ([D67]) |
| `clint_agree s m` | `!x. clint_byte s.procID x ==> (m x = s.MEM8 x)` | the replacement memory agrees on the CLINT |
| `satp_bare s` | `~MEM ((63 >< 60) (s.c_SCSR s.procID).satp) [8w; 9w; 10w]` | translation is off for S and U (P §12.1.11 Table 40 p.126); `legalize_satp` keeps reserved MODEs out, so in a reachable state this is `satp.MODE = 0` |
| `mem_access i s` | the access `(va, n, kind)` of instruction `i`, for the 37 data-memory instructions of §3.2; `NONE` otherwise | the list of memory instructions |
| `clint_inst i` | `T` for `CSRRW`, `CSRRS`, `CSRRC`, `CSRRWI`, `CSRRSI`, `CSRRCI`, `WFI` | the instructions that read the CLINT |

### 1.2 For the theorems (Stage 2, as planned; "As proved" in §2 has the changes)

The PMP permission of a byte for U-mode is the model's own check of a 1-byte access:

    pmp_U kind s x  <=>  pmpCheck (x, 1, kind, User) s          (kind = PMP_Read, PMP_Write, PMP_Execute)

Stage 2 proves the two facts that relate it to the accesses the model checks:

    pmpCheck_byte:  p <> Machine /\ pmpCheck (a, n, kind, p) s /\ (w2n a MOD n = 0) /\
                    (n = 1 \/ n = 2 \/ n = 4 \/ n = 8) /\ in_range a n x ==>
                    pmpCheck (x, 1, kind, p) s
    pmpCheck_RW:    pmpCheck (a, n, PMP_ReadWrite, p) s ==>
                    pmpCheck (a, n, PMP_Read, p) s /\ pmpCheck (a, n, PMP_Write, p) s

(`pmpCheck_byte` is §3.7.1.3: the deciding entry matches all of `[a, a + n)`, so it decides each
byte; alignment rules out the wrap of `a + (n - 1)`.)

Word level, for HolBA's contracts, which state `pmpcfg0`, `pmpcfg2`, `pmpaddr0`-`pmpaddr15` as
64-bit words: a function of those words alone, `pmp_check (cfg0, cfg2, addr) (a, n, kind, p)`,
written as the same unrolled chain of 16 entry checks over the words, with

    pmpCheck_words:  pmpCheck (a, n, kind, p) s =
                     pmp_check ((s.c_MCSR s.procID).pmpcfg0, (s.c_MCSR s.procID).pmpcfg2,
                                pmpaddr_of (s.c_MCSR s.procID)) (a, n, kind, p)

where `pmpaddr_of m i` is `m.pmpaddr<i>`. A contract that fixes those words can then evaluate
the permission of any byte with `EVAL` or bit-blasting.

The hypotheses are bundled as

    U_bare s  <=>  (curPrivilege () s = User) /\ (effectivePrivilege () s = User) /\ satp_bare s

with the lemma that HolBA discharges:

    U_bare_intro:  (s.c_privilege s.procID = 0w) /\ ~(s.c_MCSR s.procID).mstatus.MPRV /\
                   ((63 >< 60) (s.c_SCSR s.procID).satp = 0w) ==> U_bare s

The instruction that a step runs, when it takes no interrupt, is

    step_inst s = if IS_SOME (checkInterrupts () s) then NONE
                  else case FST (Fetch () s) of
                         F_Error i => SOME i
                       | F_Result (Half h) => SOME (if haveRVC () s then DecodeRVC h else UnknownInstruction)
                       | F_Result (Word w) => SOME (Decode w)

(`Next` evaluates both on the state after `clear_logs` and the reset of `c_minstret_written`,
which neither reads; Stage 2 proves that.)

### 1.3 For the region of a U-mode byte and the trap entry (built)

| Name | Definition | Meaning |
|---|---|---|
| `pmp_match_w w i x` | `?lo hi. (pmp_region w i = SOME (lo, hi)) /\ lo <=+ x /\ x <+ hi` | entry `i` of the PMP CSR words `w = (pmpcfg0, pmpcfg2, addr)` matches byte `x`: `pmp_match` over the words |
| `napot_region y` | `let m = y ?? (y + 1w); lo = (y && ~m) << 2 in (lo, lo + ((m + 1w) << 2))` | the bytes `[lo, hi)` that a NAPOT entry with address word `y` matches (Table 24 p.72): `m` has the trailing ones of `y` and the zero above them set, as in `pmp_region` |

An entry is OFF or NAPOT iff bits 4 and 3 of its configuration byte are equal; for all sixteen
entries at once this is the bit condition `(cfg >>> 1 ?? cfg) && 0x0808080808080808w = 0w` on
`pmpcfg0` and on `pmpcfg2`, the hypothesis H4 (`pmp_off_or_napot`) of the step library's
M-mode contract.

### 1.4 For the refinement of `NextRISCV` (built)

| Name | Definition | Meaning |
|---|---|---|
| `ghost_reset s` | `s with <\| log := []; c_update := K ARB; exception := NoException; c_cycles := K 0w; c_instret := K 0w; c_minstret_written := K F \|>` | `s` with the six ghost fields set to fixed values |
| `ghost_eq s t` | `ghost_reset s = ghost_reset t` | `s` and `t` agree on every field but the ghost fields |
| `counter_csr c` | `MEM c [0xB00w; 0xB02w; 0xC00w; 0xC02w]` | `mcycle`, `minstret` and their read-only shadows `cycle`, `instret` (P §3.1.10 p.46, §3.1.11 p.47) |
| `reads_counter i` | `counter_csr c` for `System (CSRRW (rd, rs1, c))` and the five other CSR instructions, `F` for every other instruction | the instruction reads a counter CSR into a register |

The ghost fields are the fields in which the two step functions differ. `Next` sets `log` to
`[]` (`clear_logs`) and `c_minstret_written` of the hart to `F`, fetches with `setupDelta`, which
writes the access record `c_update`, counts the instruction in `c_instret` (`incrInstret`, which
reads `c_minstret_written`) and the cycle in `c_cycles`; `NextRISCV` does none of this, and
returns `NONE` when `exception` is set, which `Next` never reads. The build computes the six
from the definitions (the fields that `Next`'s own definition, `clear_logs` and `incrInstret`
update, those that the spec's `Fetch` updates and the step library's does not, and those that
`NextRISCV_def` reads) and stops if they change. The instruction itself may write ghost fields
too (`writeCSR`, `writeFPRS`, `writeFPRD` log in `c_update`; a CSR write of `mcycle` or
`minstret` writes the counters); it reads one only for a counter CSR (`CSRMap`, checked).

### 1.5 For the machine timer (built)

| Name | Definition | Meaning |
|---|---|---|
| `mtime_byte x` | `in_range (CLINT_BASE + 0xBFF8w) 8 x` | `x` is a byte of `mtime` (the first disjunct of `clint_byte`) |
| `set_mtime t s` | `s with MEM8 := (\x. if mtime_byte x then (7 >< 0) (t >>> (8 * w2n (x - (CLINT_BASE + 0xBFF8w)))) else s.MEM8 x)` | the clock sets `mtime` to `t`: byte `i` of `mtime` becomes byte `i` of `t`, little-endian as `mtime ()` reads it |
| `tptick C mx v pre post` | `if C pre post /\ mtime () post <+ v /\ w2n v < mx then set_mtime v post else post` | after the step from `pre` to `post`, the environment's offer `v` sets the clock if `C` selects the transition, `v` is above `mtime` and below the bound `mx` |
| `tpexec C mx t s k` | `tpexec C mx t s 0 = s`; `tpexec C mx t s (SUC k) = tptick C mx (t k) (tpexec C mx t s k) (Next (tpexec C mx t s k))` | the tick-point execution: `k` steps of `Next`, step `i` followed by the tick of the offer `t i` |
| `texec ck s k` | `texec ck s 0 = s`; `texec ck s (SUC k) = Next (set_mtime (ck k) (texec ck s k))` | the hardware execution: the clock `ck` sets `mtime` before every step |
| `timer_mono ck` | `!k. ck k <=+ ck (SUC k)` | the clock never goes back |
| `clint_csr c` | `(c = 0xC01w) \/ (c = 0x344w) \/ (c = 0x144w)` | `time`, `mip` and `sip`, the CSRs whose read reads the CLINT |
| `noclint_inst i s` | `~clint_csr c` for the six CSR instructions on `c`; `curPrivilege () s = Machine` for WFI; `F` for every other instruction | an instruction of `clint_inst` that reads no memory |
| `kstep_noclock s` | `(curPrivilege () s = Machine) /\ ~mstatus.MIE /\ (effectivePrivilege () s = Machine)`, no byte of `fetch_bytes s` and no byte of the data that `step_inst s` reads is a byte of `mtime`, and `clint_inst i ==> noclint_inst i s` for `step_inst s = SOME i` | an M-mode step that reads no byte of `mtime` |

`tptick` and `tpexec` take the condition and the bound as parameters, so that a kernel's proof
chooses where the clock may advance (for one, after the steps that leave, enter or stay in
U-mode, and at the instructions with which the kernel reads the clock) and how far; there is no
hypothesis on the environment, whose offers the guard filters.

## 2. The theorems

### (a) Write frame

    Next_writes:
      !s x. (effectivePrivilege () s = Machine \/ satp_bare s) /\ ((Next s).MEM8 x <> s.MEM8 x) ==>
            ?i va n kind. (step_inst s = SOME i) /\ (mem_access i s = SOME (va, n, kind)) /\
                          (kind = PMP_Write \/ kind = PMP_ReadWrite) /\ (w2n va MOD n = 0) /\
                          in_range va n x /\ pmpCheck (va, n, kind, effectivePrivilege () s) s

    Next_U_writes:
      !s x. (effectivePrivilege () s = User) /\ satp_bare s /\ ((Next s).MEM8 x <> s.MEM8 x) ==>
            ?i va n kind. ... /\ pmpCheck (va, n, kind, User) s

    Next_U_writes_byte:
      !s x. (effectivePrivilege () s = User) /\ satp_bare s /\ ((Next s).MEM8 x <> s.MEM8 x) ==>
            pmpCheck (x, 1, PMP_Write, User) s

Every byte the step changes is one of the `n` bytes of the data access of the instruction it
ran, a store, SC, AMO or FP store, whose `n`-byte range at `va` passed `pmpCheck` for a write
(PMP_Write, or PMP_ReadWrite for an AMO) with the configuration of `s`. `n` is 1, 2, 4 or 8.

### (b) Fetch

    Next_U_fetch:
      !s x. (curPrivilege () s = User) /\ satp_bare s /\ fetch_bytes s x ==>
            pmpCheck (x, 1, PMP_Execute, User) s

    Next_U_fetch_fault:
      !s a. (curPrivilege () s = User) /\ satp_bare s /\ (checkInterrupts () s = NONE) /\
            fetch_fault s a ==>
            ((Next s).MEM8 = s.MEM8) /\
            (Next s = cycle_step (takeTrap (F, 1w, PC s, a, excDest (1w, User) s) (fetch_fault_state s a)))

    fetch_fault s a <=>
      ~word_bit 0 (PC s) /\ (word_bit 1 (PC s) ==> haveRVC () s) /\
      ((a = PC s) /\ ~pmpCheck (PC s, 2, PMP_Execute, User) s \/
       (a = PC s + 2w) /\ pmpCheck (PC s, 2, PMP_Execute, User) s /\
       word_bit 0 (s.MEM8 (PC s)) /\ word_bit 1 (s.MEM8 (PC s)) /\
       ~pmpCheck (PC s + 2w, 2, PMP_Execute, User) s)
    fetch_fault_state s a =
      s with <| log := []; c_minstret_written := (s.procID =+ F) s.c_minstret_written;
                c_Skip := (if a = PC s then s.c_Skip else (s.procID =+ 4w) s.c_Skip);
                c_NextFetch := (s.procID =+ NONE) s.c_NextFetch |>
    cycle_step t =
      if word_bit 0 (t.c_MCSR t.procID).mcountinhibit then t
      else t with c_cycles := (t.procID =+ t.c_cycles t.procID + 1w) t.c_cycles

The bytes the step fetches are those of `fetch_bytes` (Fetch_reads, §4.6), and each is in a
region that allows U-mode to execute. When the parcel at the pc, or the second parcel of a
32-bit instruction, is not allowed, the step is the trap entry of an instruction access fault
(code 1, P Table 16 p.50) with `mtval`/`stval` the parcel's address (P §3.1.16 p.52, [D59]),
to M or, if `medeleg` bit 1 is set, to S (`excDest`, P §3.1.8), and memory is unchanged. The
step runs exactly the instruction decoded from the fetched parcels otherwise (`step_inst`).

### (c) Read dependence

    Next_U_reads:
      !D s1 s2. U_bare s1 /\ same_except D s1 s2 /\
                (!x. D x ==> ~pmpCheck (x, 1, PMP_Read, User) s1 /\
                             ~pmpCheck (x, 1, PMP_Execute, User) s1 /\ ~clint_byte s1.procID x) ==>
                same_except D (Next s1) (Next s2)

    Next_U_secret_unchanged:
      !D s. (effectivePrivilege () s = User) /\ satp_bare s /\
            (!x. D x ==> ~pmpCheck (x, 1, PMP_Write, User) s) ==>
            !x. D x ==> ((Next s).MEM8 x = s.MEM8 x)

    pmp_legal_write_read:
      pmp_legal (s.c_MCSR s.procID) /\ pmpCheck (x, 1, PMP_Write, User) s ==>
      pmpCheck (x, 1, PMP_Read, User) s

Two U-mode states that are equal except on a set `D` of bytes that U-mode may neither read nor
execute, and that are not CLINT bytes, take steps whose results are equal except on `D`. The
PMP configuration, being outside memory, is the same in both. With `pmp_legal` (no entry has
W = 1 and R = 0, which `legalize_pmpcfg_byte` maintains, [D49]), such bytes are not writable
either, so each step leaves them unchanged (`Next_U_secret_unchanged`, from (a)).

The proof characterises the bytes the step reads (§3.3): the CLINT bytes of the hart (the
interrupt check), the fetched parcels (`fetch_bytes`), the data read by the instruction
(`data_bytes` of its `mem_access`, for kinds PMP_Read and PMP_ReadWrite), and the CLINT bytes
again for a CSR instruction (the `time` CSR is `mtime`). In Bare U-mode the first two are
allowed to execute or are CLINT bytes, and the third is allowed to be read (`pmpCheck_byte`,
`pmpCheck_RW`).

### (d) Companion frames

    Next_U_frame:
      !s. (curPrivilege () s = User) /\ (s.c_NextFetch s.procID = NONE) ==>
          let t = Next s; m = s.c_MCSR s.procID; m' = t.c_MCSR s.procID;
              c = s.c_SCSR s.procID; c' = t.c_SCSR s.procID in
          (t.procID = s.procID) /\ (t.totalCore = s.totalCore) /\
          (* the M-mode CSRs that no trap entry writes *)
          (m'.misa = m.misa) /\ (m'.mhartid = m.mhartid) /\ (m'.medeleg = m.medeleg) /\
          (m'.mideleg = m.mideleg) /\ (m'.mie = m.mie) /\ (m'.mtvec = m.mtvec) /\
          (m'.mcounteren = m.mcounteren) /\ (m'.menvcfg = m.menvcfg) /\
          (m'.mcountinhibit = m.mcountinhibit) /\ (m'.mscratch = m.mscratch) /\ (m'.mip = m.mip) /\
          (m'.pmpcfg0 = m.pmpcfg0) /\ (m'.pmpcfg2 = m.pmpcfg2) /\ (!i. pmpaddr i t = pmpaddr i s) /\
          (* the S-mode CSRs that no trap entry writes *)
          (c'.satp = c.satp) /\ (c'.stvec = c.stvec) /\ (c'.scounteren = c.scounteren) /\
          (c'.senvcfg = c.senvcfg) /\ (c'.sscratch = c.sscratch) /\
          (* mstatus outside the trap-entry fields and FS *)
          (mstatus_nontrap m'.mstatus = mstatus_nontrap m.mstatus) /\
          ((m'.mstatus.FS = m.mstatus.FS) \/ (m'.mstatus.FS = 3w)) /\
          (* floating point state when FS = Off *)
          ((m.mstatus.FS = 0w) ==> (t.c_fpr s.procID = s.c_fpr s.procID) /\
                                   (t.c_UCSR s.procID = s.c_UCSR s.procID)) /\
          (* the load reservation, only by LR and SC *)
          ((t.c_ReserveLoad s.procID <> s.c_ReserveLoad s.procID) ==>
           ?i. (step_inst s = SOME i) /\ lr_sc i)
      where mstatus_nontrap ms = ms with <| MIE := F; MPIE := F; MPP := 0w; SIE := F; SPIE := F;
                                            SPP := F; FS := 0w |>

    Next_U_trap:
      !s. (curPrivilege () s = User) /\ (s.c_NextFetch s.procID = NONE) ==>
          ((Next s).c_privilege s.procID = s.c_privilege s.procID) /\ trap_fields_same s (Next s)
          \/
          ((Next s).MEM8 = s.MEM8) /\
          ?intr ec tval d t.
            (Next s = cycle_step (takeTrap (intr, ec, PC s, tval, d) t)) /\
            (if intr then ?i. (checkInterrupts () s = SOME (i, d)) /\ (ec = interruptIndex i)
             else (d = excDest (ec, User) s)) /\
            (t.c_MCSR = s.c_MCSR) /\ (t.c_SCSR = s.c_SCSR) /\ (t.c_privilege = s.c_privilege) /\
            (t.c_PC = s.c_PC) /\ (t.MEM8 = s.MEM8) /\ (t.procID = s.procID)

    trap_fields_same s t <=>
      let m = s.c_MCSR s.procID; m' = t.c_MCSR s.procID;
          c = s.c_SCSR s.procID; c' = t.c_SCSR s.procID in
      (m'.mepc = m.mepc) /\ (m'.mcause = m.mcause) /\ (m'.mtval = m.mtval) /\
      (c'.sepc = c.sepc) /\ (c'.scause = c.scause) /\ (c'.stval = c.stval) /\
      (m'.mstatus.MIE = m.mstatus.MIE) /\ (m'.mstatus.MPIE = m.mstatus.MPIE) /\
      (m'.mstatus.MPP = m.mstatus.MPP) /\ (m'.mstatus.SIE = m.mstatus.SIE) /\
      (m'.mstatus.SPIE = m.mstatus.SPIE) /\ (m'.mstatus.SPP = m.mstatus.SPP)
    lr_sc i <=> (?a. (i = AMO (LR_W a)) \/ (i = AMO (LR_D a))) \/
                (?b. (i = AMO (SC_W b)) \/ (i = AMO (SC_D b)))
    pmp_legal m <=> !i. ~(pmpcfg_of m i).W \/ (pmpcfg_of m i).R
      (pmpcfg_of m i: the byte of entry i of m.pmpcfg0 / m.pmpcfg2, as pmpcfg_ent reads it)

`Next_U_frame` lists the state that a U-mode step leaves alone or changes only by a trap entry:
the M-mode CSRs other than `mepc`, `mcause`, `mtval` and the trap fields of `mstatus` (MIE, MPIE,
MPP, P §3.1.6.1 p.32), the S-mode CSRs other than `sepc`, `scause`, `stval` and SIE, SPIE, SPP;
the PMP CSRs and `satp` among them. FS may become Dirty (3) through an F/D instruction or an
`fcsr` write when FS is not Off (P §3.1.6.7 p.38); when it is Off those are illegal, so the FPRs
and `fcsr` do not change. `Next_U_trap`: either the privilege is unchanged and no trap field
changed, or the step was a trap entry (`takeTrap`, DP §4.6), to M or to S as `mideleg` or
`medeleg` delegate (P §3.1.8; DP §4.4; `takeTrap` never goes to U), from a state `t` with the
same CSRs, privilege, pc and memory as `s` (a trapping instruction has changed no M-level CSR
and no memory before signalling: "PMP violations are always trapped precisely", P §3.7 p.70,
DP §5.5; its effect on the GPRs, FPRs and the reservation is not stated), and the memory is
unchanged.

The hypothesis `c_NextFetch = NONE` is an invariant of reachable states between steps (`Next`
resets it in every branch); without it a stale `SOME Mret` would make `Next` perform an MRET
after a U-mode instruction.

### Hypotheses, and why each is needed

| Hypothesis | Needed by | Why |
|---|---|---|
| `effectivePrivilege () s = User` | (a), (c) | explicit loads and stores are checked with the effective privilege (P §3.1.6.4 p.35, [D22]); with MPRV = 1 and MPP = M a U-mode store would be checked as M. In a reachable U-mode state MPRV = 0 (an xRET that leaves M clears it), so this is `~MPRV`. |
| `curPrivilege () s = User` | (b), (c), (d) | fetches use the current privilege; it is what makes the step a U-mode step (CSR and xRET legality, interrupt enables). |
| `satp_bare s` | (a), (b), (c) | the translated case is out of scope: with translation the physical address and the PTE reads would be part of the statements. Only Sv39/Sv48/Sv57 activate translation, so this is weaker than `satp.MODE = 0`. |
| `checkInterrupts () s = NONE` | (b) | a step that takes an interrupt fetches nothing (P §3.1.14 p.49, [D38]). |
| `D` has no CLINT byte | (c) | the interrupt check reads `mtime` and `mtimecmp` (MTIP, P §3.2.1 p.59) and `msip` (P §3.1.9 p.44) from memory ([D67]) without a PMP check, and so does a CSR read of `time`: two states that differ there may differ in whether a timer interrupt is taken. This is the platform's timer, not a PMP leak. |
| `c_NextFetch = NONE` | (d) | as above. |

### (e) The region of a byte that U-mode may access (`riscv_pmpTheory`, built)

(a)-(c) say that a U-mode step touches only bytes `x` with `pmpCheck (x, 1, kind, User) s`.
A kernel that relates the PMP configuration to its own records of who owns which memory needs
to know where such a byte lies. For U-mode the first matching entry decides and some entry must
match (§3.7.1.3 p.73); with only OFF and NAPOT entries, that entry's region is the NAPOT region
of its own address word:

    pmpCheck_User_entry:
      !x kind s.
        pmpCheck (x, 1, kind, User) s ==>
        ?i lo hi. i < 16 /\ (pmpRegion (n2w i) s = SOME (lo, hi)) /\ lo <=+ x /\ x <+ hi /\
                  pmpPermits (pmpcfg_ent (n2w i) s, kind) /\
                  !j. j < i ==> ~pmp_match s (n2w j) x

    pmp_check_User_byte:
      !w x kind.
        pmp_check w (x, 1, kind, User) <=>
        ?i. i < 16 /\ pmp_match_w w (n2w i) x /\ (!j. j < i ==> ~pmp_match_w w (n2w j) x) /\
            pmp_perm (pmp_cfg_byte (FST w) (FST (SND w)) (n2w i)) kind

    pmp_check_User_napot:
      !cfg0 cfg2 addr x kind.
        ((cfg0 >>> 1 ?? cfg0) && 0x0808080808080808w = 0w) /\
        ((cfg2 >>> 1 ?? cfg2) && 0x0808080808080808w = 0w) /\
        pmp_check (cfg0, cfg2, addr) (x, 1, kind, User) ==>
        ?i. i < 16 /\ ((4 >< 3) (pmp_cfg_byte cfg0 cfg2 (n2w i)) = 3w : word2) /\
            pmp_perm (pmp_cfg_byte cfg0 cfg2 (n2w i)) kind /\
            FST (napot_region (addr (n2w i))) <=+ x /\ x <+ SND (napot_region (addr (n2w i))) /\
            !j. j < i ==> ~pmp_match_w (cfg0, cfg2, addr) (n2w j) x

`pmpCheck_User_napot` is `pmp_check_User_napot` for a state, with `(s.c_MCSR s.procID).pmpcfg0`,
`(s.c_MCSR s.procID).pmpcfg2` and `\k. pmpaddr k s` for the words (so `pmpaddr (n2w i) s` for
`addr (n2w i)`), by `pmpCheck_words`. The steps: `pmp_entry_User_byte` (a 1-byte User access
gets the verdict `NONE` from an entry that does not match it and `pmp_perm` of the entry's byte
from one that does), `pmp_first_GENLIST` (the first verdict decides), `off_or_napot_bytes` (the
bit condition makes every A field 0 or 3) and `pmp_region_off_napot` (an OFF entry has no region,
a NAPOT entry has `napot_region` of its address word). `pmpRegion_pmpcfg2_off` and
`pmpCheck_User_low` add that with `pmpcfg2 = 0` entries 8-15 are OFF, so the deciding entry is
one of 0-7. An aligned access of 2, 4 or 8 bytes is covered byte by byte through
`pmpCheck_byte`.

### (f) Trap entry from U-mode (`riscv_trapTheory`, built)

`Next_U_trap` says that a U-mode step that traps is some `takeTrap` from a state with the CSRs,
privilege, pc and memory of `s`, but not with which cause (and so not into which mode), with
which trap value, or what happens to the GPRs. For the step by which a process makes a system
call, all of that is determined:

    Next_U_ecall:
      !s. (curPrivilege () s = User) /\ (step_inst s = SOME (System ECALL)) /\
          ~word_bit 8 (s.c_MCSR s.procID).medeleg ==>
          ((Next s).procID = s.procID) /\ ((Next s).c_privilege s.procID = 3w) /\
          ((Next s).c_PC s.procID = trapVector ((s.c_MCSR s.procID).mtvec, F, 8w)) /\
          (((Next s).c_MCSR s.procID).mcause = <| EC := 8w; Int := F |>) /\
          (((Next s).c_MCSR s.procID).mepc = PC s) /\ (((Next s).c_MCSR s.procID).mtval = 0w) /\
          (((Next s).c_MCSR s.procID).mstatus =
             (s.c_MCSR s.procID).mstatus with
               <| MIE := F; MPIE := (s.c_MCSR s.procID).mstatus.MIE; MPP := 0w |>) /\
          ((Next s).c_MCSR s.procID with
             <| mcause := (s.c_MCSR s.procID).mcause; mepc := (s.c_MCSR s.procID).mepc;
                mtval := (s.c_MCSR s.procID).mtval; mstatus := (s.c_MCSR s.procID).mstatus |> =
           s.c_MCSR s.procID) /\
          ((Next s).c_SCSR = s.c_SCSR) /\ ((Next s).c_gpr = s.c_gpr) /\ ((Next s).MEM8 = s.MEM8) /\
          ((Next s).c_NextFetch s.procID = NONE) /\ ((Next s).exception = s.exception)

ECALL raises the environment call from U-mode, cause 8 (P §3.3.1 p.60-61, Table 16 p.50);
not delegated (P §3.1.8 p.42), it is taken into M-mode, which writes `mcause`, `mepc` (the pc
of the `ecall`) and `mtval` (0, P §3.1.16 p.53), sets MPIE to MIE, MIE to 0 and MPP to U
(P §3.1.6.1 p.32), the privilege to M and the pc to the trap vector (P §3.1.7 p.41). The
statement lists the four trap fields and puts them back in one record equation, so that every
other M-level CSR of the hart (the PMP CSRs, `mtvec`, `mscratch`, `misa`, ...) is unchanged
without being named; the S-level CSRs, the GPRs and memory are unchanged as whole functions.

Which steps take no interrupt, and what that says of the timer:

    checkInterrupts_U_MTIP:
      !s. (curPrivilege () s = User) /\ word_bit 7 (reg'mie (s.c_MCSR s.procID).mie) /\
          (checkInterrupts () s = NONE) ==>
          ~(mtimecmp s.procID s <=+ mtime () s)

    Next_U_stays_no_interrupt:
      !s. (s.c_privilege s.procID = 0w) /\
          ((Next s).c_privilege s.procID = s.c_privilege s.procID) ==>
          (checkInterrupts () s = NONE)

In U-mode both branches of `checkInterrupts` are enabled: an interrupt pending and enabled in
`mie` is taken into M if `mideleg` does not delegate it and into S if it does (P §3.1.9 p.43,
§12.1.3 p.117), so with MTIE set and no interrupt taken MTIP is clear, whatever `mideleg`
holds; `read_mip` computes MTIP as `mtimecmp <=+ mtime` from the CLINT (P §3.2.1 p.59, [D67]).
An interrupt is taken into M or S and changes the privilege of a U-mode hart, so a step that
keeps the privilege took none. With `step_inst_SOME` (a step that runs an instruction took no
interrupt), a kernel that keeps MTIE set can conclude from either kind of step from U-mode, one
that stays in U-mode or one that runs ECALL, that no timer interrupt was pending at its start.

The words: `reg'mcause_8` (`reg'mcause c = 8w` iff `c.EC = 8w` and `~c.Int`, P §3.1.15 Figure 22
p.49), `trapVector_direct` (`(1 >< 0) tvec = 0w ==> trapVector (tvec, intr, ec) = tvec`: in
Direct mode every trap goes to BASE, which is `mtvec` itself, Table 15 p.41) and
`trapVector_exception` (`trapVector (tvec, F, ec) = tvec && ~3w`). Helpers: `Fetch_exception`
and `exec_state_exception` (the spec's `Fetch` returns `F_Error` instead of raising, so it keeps
the `exception` field), `curPrivilege_User` (privilege 0 or the reserved 2).

`riscv_trap_exampleTheory` instantiates these on the region of `riscv_isolation_exampleTheory`
(`ex_ecall`, `ex_timer_only`) and gives a concrete state that runs `ecall` there
(`ex_ecall_state_witness`, `ex_ecall_witness_trap`), so the hypotheses of `Next_U_ecall` can hold
together.

As proved, compared with the statements these theorems were designed with: all are as designed
but `pmpCheck_User_low`, which has in addition the conjunct `!j. j < i ==> ~pmp_match s (n2w j)
x` (the deciding entry is the first that matches). Theorems added: `pmp_match_words`,
`step_inst_SOME`, `curPrivilege_User`, `exec_state_exception`, `trapVector_exception`.

### (g) `Next` and the step library's `NextRISCV` (`riscv_refineTheory`, built)

The step library's theorems are about `NextRISCV`, the M-mode step that HolBA's lifter and
backlifter use; the theorems above are about `Next`. They agree but for the ghost fields
(§1.4), as long as the instruction reads no counter CSR:

    Fetch_step_spec:
      !s w s1. (riscv_step$Fetch s = (w, s1)) /\ (s.exception = NoException) /\
               (s1.exception = NoException) ==>
               ?u. riscv$Fetch () s = (F_Result w, s1 with c_update := u)

    Run_ghost:
      !i s t. ~reads_counter i /\ ghost_eq s t ==> ghost_eq (Run i s) (Run i t)

    Next_NextRISCV_ghost:
      !s t t'. ghost_eq s t /\ (checkInterrupts () t = NONE) /\
               (!w t1. (riscv_step$Fetch t = (w, t1)) ==>
                       ~reads_counter (DecodeAny (haveRVC () t) w)) /\
               (NextRISCV t = SOME t') ==>
               ghost_eq (Next s) t'

    Next_ghost:
      !s t. ghost_eq s t /\ (!i. (step_inst s = SOME i) ==> ~reads_counter i) ==>
            ghost_eq (Next s) (Next t)

Where the step library's fetch succeeds, the spec's reads the same bits and leaves the same
state but for its access record; an instruction that reads no counter maps ghost-equal states
to ghost-equal states; and a `NextRISCV` step from a state that takes no interrupt is, up to the
ghost fields, the `Next` step of every ghost-equal state. `Next` takes the interrupt that
`checkInterrupts` finds and `NextRISCV` takes none, hence that hypothesis; `NextRISCV` returns
`NONE` after a failed fetch (its `Fetch` raises an exception where the spec's returns
`F_Error`), after an exception, and for SRET.

They rest on one lemma per function reachable from `Next` (`<f>_ghost`, the build checks that
every function has one but `Delta` and `fetchAndExecute`):

    f x (ghost_reset s) = ghost_reset (f x s)                        (187 functions, generated)
    ghost_eq s t ==> ghost_eq (f x s) (f x t)   [and equal values]   (the others)

with `~counter_csr c` for the value of a CSR read and for the CSR instructions. A function whose
only effect on the state is on ghost fields has the stronger `ghost_eq (f x s) s`
(`write'Delta_ghost`, `clear_logs_ghost`, `incrInstret_ghost`, `raise'exception_ghost`,
`CSRMap_state`, `cycle_step_ghost`, `next_pre_ghost`). `Run_exception` says that an instruction
never clears a raised exception, which is what makes `NextRISCV t = SOME t'` exclude a failed
fetch (`Fetch_step_exception`, `NextRISCV_exception`).

As proved, compared with the statements these theorems were designed with: `ghost_reset_def`,
`ghost_eq_def`, `counter_csr_def`, `reads_counter_def`, `Fetch_step_spec`, `Run_ghost` and
`Next_NextRISCV_ghost` are as designed. The generated lemmas commute with `ghost_reset` as a
whole, one lemma per function, where the design had one commutation with an update of each
ghost field that the function does not mention; the per-field commutation is proved for
`exception` alone (for a value other than `NoException`, for `Run` and every function reachable
from it, locally), which `Run_exception` needs. `CSRMap_ghost` and `CSR_ghost` state the
ghost-equality of the states for every CSR and the equality of the values for a CSR other than
a counter (designed: both under `~counter_csr`); `write'CSRMap_ghost`, `write'CSR_ghost` and
`writeCSR_ghost` hold for every CSR. `Delta`, whose value is the ghost field `c_update`, has no
lemma; `fetchAndExecute` none of its own (`Next_ghost`, `Next_NextRISCV_ghost` cover it).
Theorems added: `Next_ghost`, `Run_exception`, `Fetch_spec_step`, `Fetch_step_exception`,
`NextRISCV_exception`, `NextRISCV_next_post`, `next_post_ghost`, `cycle_step_ghost`,
`next_pre_ghost`, `exec_state_ghost`, `writeCSR_write'CSRMap`, `CSRMap_state`, and
`ghost_eq_refl`, `ghost_eq_sym`, `ghost_eq_trans`, `ghost_eq_reset`, `ghost_reset_idem`,
`ghost_eq_fields`, `ghost_eq_ghost_fupd`.

`riscv_refine_exampleTheory` instantiates `Next_NextRISCV_ghost` on the step library's theorems
of `csrw pmpcfg0, t0`, `sd x6, 0(x5)`, `c.jr ra`, `beq x0, x0, 8` and `mret`, discharging the
no-interrupt and fetch hypotheses from those of each step theorem (`checkInterrupts_Machine`,
`Fetch32`, `Fetch16`, the step library's decoder), so that `<name>_refine` has exactly the step
theorem's hypotheses; `cycle_read_refused` shows that `csrr a0, cycle` reads a counter, and the
build checks that the instance fails for it.

### (h) The machine timer (`riscv_timerTheory`, built)

The clock. `set_mtime` writes the eight bytes that `mtime ()` reads, so

    mtime_set_mtime:           !v s. mtime () (set_mtime v s) = v
    mtimecmp_set_mtime:        !v s h. mtimecmp h (set_mtime v s) = mtimecmp h s
    same_except_set_mtime:     !t s. same_except mtime_byte s (set_mtime t s)
    same_except_set_mtime_eq:  !v s1 s2. same_except mtime_byte s1 s2 ==> (set_mtime v s1 = set_mtime v s2)
    set_mtime_id:              !v s z. (!x. mtime_byte x ==> (z.MEM8 x = (set_mtime v s).MEM8 x)) ==>
                                       (set_mtime v z = z)

with `same_except_sym` and `same_except_trans` for `same_except D`. The `mtimecmp` doubleword of
a hart (`CLINT_BASE + 0x4000 + 8h`, `h` a byte) never overlaps `mtime` (`CLINT_BASE + 0xBFF8`).

The tick-point execution:

    tpexec_shift:    !C mx t s j i. tpexec C mx t s (j + i) = tpexec C mx (\m. t (j + m)) (tpexec C mx t s j) i
    tpexec_segment:  !C mx t x d. (!i. i + 1 < d ==> ~C (FUNPOW Next i x) (FUNPOW Next (SUC i) x)) ==>
                                  !i. i < d ==> (tpexec C mx t x i = FUNPOW Next i x)
    tpexec_stopped:  !C mx s k. tpexec C mx (K 0w) s k = FUNPOW Next k s

with `tptick_same_except` (a tick changes only the bytes of `mtime`), `mtime_tptick` and
`mtimecmp_tptick`. `tpexec_segment` is how a run of `Next` that some other theorem describes
(a contract of a kernel, a sequence of step theorems) becomes a segment of the execution: no
transition strictly inside it may be one that `C` selects.

The timer interrupt. In U-mode an interrupt that is pending, enabled in `mie` and not delegated
is taken into M-mode whatever `mstatus.MIE` is, the first in the order MEI, MSI, MTI, SEI, SSI,
STI (P §3.1.9 p.43-45); one that is delegated is taken into S-mode if none is taken into M:

    checkInterrupts_U_timer_pending:
      !s. (curPrivilege () s = User) /\ word_bit 7 (reg'mie (s.c_MCSR s.procID).mie) /\
          ~word_bit 7 (s.c_MCSR s.procID).mideleg /\
          (reg'mie (s.c_MCSR s.procID).mie && 0x808w = 0w) /\
          (mtimecmp s.procID s <=+ mtime () s) ==>
          (checkInterrupts () s = SOME (MTI, Machine))

    checkInterrupts_U_timer:
      !s. (curPrivilege () s = User) /\ word_bit 7 (reg'mie (s.c_MCSR s.procID).mie) /\
          ~word_bit 7 (s.c_MCSR s.procID).mideleg /\
          (reg'mie (s.c_MCSR s.procID).mie && 0xA2Aw = 0w) ==>
          (checkInterrupts () s =
             if mtimecmp s.procID s <=+ mtime () s then SOME (MTI, Machine) else NONE)

    Next_U_timer:
      !s. <the hypotheses of checkInterrupts_U_timer_pending> ==>
          (step_inst s = NONE) /\ ((Next s).procID = s.procID) /\
          ((Next s).c_privilege s.procID = 3w) /\
          ((Next s).c_PC s.procID = trapVector ((s.c_MCSR s.procID).mtvec, T, 7w)) /\
          (((Next s).c_MCSR s.procID).mcause = <| EC := 7w; Int := T |>) /\
          (((Next s).c_MCSR s.procID).mepc = PC s) /\ (((Next s).c_MCSR s.procID).mtval = 0w) /\
          (((Next s).c_MCSR s.procID).mstatus =
             (s.c_MCSR s.procID).mstatus with
               <| MIE := F; MPIE := (s.c_MCSR s.procID).mstatus.MIE; MPP := 0w |>) /\
          ((Next s).c_MCSR s.procID with
             <| mcause := (s.c_MCSR s.procID).mcause; mepc := (s.c_MCSR s.procID).mepc;
                mtval := (s.c_MCSR s.procID).mtval; mstatus := (s.c_MCSR s.procID).mstatus |> =
           s.c_MCSR s.procID) /\
          ((Next s).c_SCSR = s.c_SCSR) /\ ((Next s).c_gpr = s.c_gpr) /\ ((Next s).c_fpr = s.c_fpr) /\
          ((Next s).MEM8 = s.MEM8) /\ ((Next s).c_ReserveLoad = s.c_ReserveLoad) /\
          ((Next s).c_NextFetch = s.c_NextFetch) /\ ((Next s).exception = s.exception)

    reg'mcause_timer:     !c. (reg'mcause c = 0x8000000000000007w) <=> (c.EC = 7w) /\ c.Int
    Next_M_no_interrupt:  !s m. (s.c_privilege s.procID = 3w) /\ ~(s.c_MCSR s.procID).mstatus.MIE ==>
                                (checkInterrupts () (s with MEM8 := m) = NONE) /\
                                IS_SOME (step_inst (s with MEM8 := m))
    dfn'WFI_Machine:      !s. (curPrivilege () s = Machine) ==> (dfn'WFI s = s)

with `read_mip_MTIP` (`read_mip () s && 128w` is `128w` exactly when `mtimecmp <=+ mtime`). The
hypotheses are on the bits that matter (I27): for a pending timer interrupt to be the one taken,
MTIE set and not delegated and the two interrupts that come before it, MEI and MSI, disabled
(delegated would also do); for no interrupt to be taken while it is not pending, every other
interrupt disabled
(`ex_ssi_taken` evaluates a state that meets the first hypotheses, with SSIE set, from which the
supervisor software interrupt is taken while the timer interrupt is not pending). With
`mie` = MTIE and `mideleg` = 0 both hold (`ex_timer_only_checkInterrupts`,
`ex_timer_only_Next`). The trap state is stated as `Next_U_ecall`'s (I15), with the FPRs and the
load reservation in addition, which the trap entry keeps ([D45]).

M-mode steps and a change of bytes that they do not read:

    Next_reads_M:
      !D s1 s2.
        (curPrivilege () s1 = Machine) /\ ~(s1.c_MCSR s1.procID).mstatus.MIE /\
        (effectivePrivilege () s1 = Machine) /\ same_except D s1 s2 /\
        (!x. fetch_bytes s1 x ==> ~D x) /\
        (!i acc x. (step_inst s1 = SOME i) /\ (mem_access i s1 = SOME acc) /\
                   (SND (SND acc) <> PMP_Write) /\ data_bytes acc s1 x ==> ~D x) /\
        (!i. (step_inst s1 = SOME i) /\ clint_inst i /\ ~noclint_inst i s1 ==>
             !x. clint_byte s1.procID x ==> ~D x) ==>
        same_except D (Next s1) (Next s2)

`Next_reads` (§2 (c)) needs `D` to miss the CLINT bytes because the interrupt check reads them;
in M-mode with MIE clear the check gives `NONE` for every memory (`Next_M_no_interrupt`), so
only the instruction can read the CLINT, and only a CSR instruction on `time`, `mip` or `sip`,
or WFI outside M-mode, does (`CSRMap_noclint`, `writeCSR_noclint`, `accessCSR_noclint`,
`dfn'CSRR*_noclint`, `WFI_M_comm`, `Run_noclint`, `Run_reads_M`).

The hardware execution. With `kstep_noclock` (§1.5), `noclock_step` is `Next_reads_M` for the
bytes of `mtime` after a tick, and

    texec_defer_read:
      !ck s0 j r d y.
        (set_mtime (ck (j + r)) (texec ck s0 j) = y) /\ r <= d /\
        (!i. i <= d /\ i <> r ==> kstep_noclock (FUNPOW Next i y)) /\
        (!i x. i < r /\ mtime_byte x ==>
               ((FUNPOW Next (SUC i) y).MEM8 x = (FUNPOW Next i y).MEM8 x)) ==>
        same_except mtime_byte (texec ck s0 (j + SUC d)) (FUNPOW Next (SUC d) y)

Along `d + 1` steps of which only step `r` may read the clock, and none before it writes
`mtime`, the hardware execution agrees, but for the bytes of `mtime`, with the run of `Next`
from the state at index `j` with the clock that step `r` sees; `texec_defer` is the case
`r = 0`. So a kernel's proof over the tick-point execution, whose ticks it places at the start
of such segments, carries over to the hardware execution with the tick carrying the clock of
the segment's read, provided that each segment reads the clock at most once and that
`kstep_noclock` holds at its other steps.

`riscv_timer_exampleTheory` evaluates, by EVAL from the definitions of the model, the step of a
concrete U-mode state with the timer interrupt pending (`ex_timer_step`: the trap vector,
`mcause` 7 with the interrupt bit, `mepc` the pc, GPRs and memory unchanged), derives the same
from `Next_U_timer` (`ex_timer_hyps`, `ex_timer_trap`), and runs that step in the tick-point
execution with the stopped clock (`ex_timer_stopped`, `tpexec_stopped`) and with a clock that
advances after the step out of U-mode (`ex_timer_tick_trap`); `ex_timer_tick` is a tick that
makes the timer interrupt pending, and `ex_ssi_taken` the state that shows the need for the
hypothesis of `checkInterrupts_U_timer`.

Theorems that support these: `timer_mono_le` (a monotone clock is monotone over any interval),
`noclint_mem_access`, `noclint_inst_priv`, `curPrivilege_Machine`.

## 3. The memory paths of the model

### 3.1 How the list is computed and shown exhaustive

`riscv_footprintScript.sml` (section 2) computes, from the definitions in `riscvTheory`, the
functions reachable from `Next` (253 that involve the state) and classifies each: it touches
memory iff its definition mentions the field `MEM8`, read or updated, or calls a function that
does. It asserts that the 67 that touch memory are exactly the list below, so a change to the
model that adds a memory access stops the build. The other 186 are each proved to commute with
replacing the memory (`<f>_MEM8`), so they neither read nor write it. `Run_writes` and
`Run_reads` (§4.7) then cover every instruction: an instruction that `mem_access` does not
list changes no memory, and one that neither `mem_access` nor `clint_inst` lists reads none.

## 4. Proof architecture

### 4.1 Structural, over the spec's definitions

The theorems are proved over the HOL definitions that L3 exports, not with `riscv_stepLib`. The
step library evaluates one instruction word at a time under the M-mode hypotheses of its
`contract_hyps`, and its theorems are about `NextRISCV`, which takes no interrupts. Theorems
(a)-(d) quantify over every instruction a U-mode process could run, and over interrupts, so a
per-encoding evaluation would need a U-mode hypothesis set and an enumeration of the
instruction space, and still would not cover `Next`. The structural route covers every
definition once: the memory behaviour of a definition follows from those of the functions it
calls, and 186 of the 253 functions do not touch memory at all. Every lemma is stated against
`Next` and the functions it calls, and with no hypothesis on the privilege or `satp` except
where translation must be off.

The proofs use two forms:

- commutation with replacing the memory, `f x (s with MEM8 := m) = f x s with MEM8 := m`
  (state transformers; value-and-state and value-only functions analogously), for functions
  that do not touch memory, possibly under a hypothesis that `m` agrees with `s.MEM8` on the
  bytes the function reads (`clint_agree`, the fetched parcels);
- `same_except D` for the instructions that write memory: two states equal except on `D` give
  results equal except on `D`. Writes need no exact write set in this form.

`MEM8_comm_frame` and `same_except_comm` convert the first form into frames and into the
second.

### 4.2 Layer 1: the 186 functions that do not touch memory (generated)

One tactic proves `f_MEM8` for each, in the order of the call graph, with the lemmas of the
callees (`riscv_footprintScript.sml` section 2): rewrite with the definition and the callees'
lemmas, float the memory update out of conditionals, split the remaining case expressions.
`write_pmpaddr` needs a case split on the 4-bit index, because its catch-all case is `ARB`. It
also proves `f_procID` (the hart is unchanged) for the 153 state transformers, and `f_MEM8_frame`
for them by `MEM8_comm_frame`.

### 4.3 Layer 2: memory primitives byte by byte

- `write'MEM_bytes`: byte `k` of doubleword `i` becomes byte `k` of the value.
- `rawReadData_bytes`: `rawReadData a s` is the 8 bytes from `a`, at every alignment (the
  misaligned branch reads two doublewords and shifts).
- `rawWriteData_bytes`, `rawWriteData_eq`: for `n` in {1, 2, 4, 8} and every alignment, the
  `n` bytes from `a` get the low bytes of the data and every other byte keeps its value, also
  the other bytes of the doubleword(s) rewritten. 32 width/offset cases, each a bit-blasting
  problem on 1 or 2 doublewords. No alignment hypothesis, so that the instruction
  lemmas need none on the physical address.
- `rawWriteData_MEM8`: hence the result on a replaced memory is the replacement outside the
  written bytes.
- `rawReadData_agree_1/2/4/8`: the low 1, 2, 4, 8 bytes of `rawReadData pa` depend only on
  the bytes from `pa` that the load uses.
- `rawReadInst_eq`.

### 4.4 Layer 3: address translation and the PMP check of an access

- `translateAddr_off`: with privilege M or `satp_bare`, the identity (DS §1.2, [S1]).
- `dataAddr_off`, `fetchAddr_off`: then an access is `TR_Address va` iff `pmpCheck` holds for
  its `n` bytes at `va` with the effective (data) or current (fetch) privilege.
- `dataAddr_pmpCheck`, `fetchAddr_pmpCheck`: whatever the translation, an approved physical
  address passed `pmpCheck` for the privilege of the access (DP §5.6.3).
- `dataAddr_off_MEM8`, `fetchAddr_off_MEM8`: with translation off they read no memory.
- `align_tests`: the instructions' alignment tests are natural alignment.

### 4.5 Layer 4: the CLINT readers

`mtime_CLINT`, `mtimecmp_CLINT`, `msip_CLINT`, `read_mip_CLINT`, `checkInterrupts_CLINT`,
`CSRMap_CLINT`, `writeCSR_CLINT`, `accessCSR_CLINT`, `dfn'WFI_CLINT`: commutation under
`clint_agree`; `CSRMap_frame`.

### 4.6 Layer 5: instructions and fetch

For each of the 37 data instructions, with access `(va, n, kind)`:

- `<I>_writes` (kind PMP_Write or PMP_ReadWrite): `(I args s).MEM8 x <> s.MEM8 x ==> data_bytes (va, n, kind) s x`;
- `<I>_MEM8_frame` (kind PMP_Read): `(I args s).MEM8 = s.MEM8`;
- `<I>_reads`: `same_except D s1 s2 /\ (!x. data_bytes (va, n, kind) s1 x ==> ~D x)` (omitted for
  PMP_Write) `/\ (dataAddr (va, n, kind) s2 = dataAddr (va, n, kind) s1) ==> same_except D (I args s1) (I args s2)`.

`va` is `GPR rs1 s + sw2sw offs` for loads, stores and F/D accesses and `GPR rs1 s` for LR, SC
and AMOs. For the CSR instructions and WFI, `<I>_MEM8_frame` and `<I>_reads` with `clint_byte`
in place of `data_bytes`. For fetch: `Fetch_MEM8`, `Fetch_MEM8_frame`, `Fetch_reads` (with
`fetch_bytes`), `fetchAddr_Skip` (the second parcel is translated after `rawReadInst` sets
`Skip`), `fetch_bytes_off`.

### 4.7 Layer 6: Run

`Run_writes`: `(Run i s).MEM8 x <> s.MEM8 x ==> ?acc. (mem_access i s = SOME acc) /\ (SND (SND
acc) <> PMP_Read) /\ data_bytes acc s x`. `Run_reads`: `same_except D` is preserved given that
`D` misses the instruction's data reads and, for `clint_inst` instructions, the CLINT bytes, and
that `dataAddr` of its access agrees. `Run_MEM8_frame`. One case analysis over the instruction
datatype, using the lemmas of layers 1 and 5.

### 4.8 Layer 7 (Stage 2): Next and theorems (a)-(d), as built

1. `Next_split`: `Next s` is `cycle_step` of either `takeTrap (T, interruptIndex i, PC s, 0w,
   p) (next_pre s)` (an interrupt) or `next_post b (fetchAndExecute () (next_pre s))`, where
   `next_pre` is `clear_logs` and the reset of `c_minstret_written`, `next_post` the
   `NextFetch` dispatch and `cycle_step` the cycle count. `Fetch` and `checkInterrupts` commute
   with `next_pre` (`Fetch_next_pre`, `checkInterrupts_next_pre`, from the `_log` and
   `_minstret` lemmas of `riscv_framesTheory`), so `step_inst s` reads `s` itself, and
   `Next_inst` gives `Next s` as `next_post` of `Run i (exec_state s)`, where `exec_state s`
   has the registers, CSRs, privilege and memory of `s` (`exec_state_fields`).
2. `riscv_framesTheory` (generated, like layer 1): for every function reachable from `Next` but
   `Next`, `fetchAndExecute` and `Run`, the fields it never updates are unchanged (`<f>_frame`,
   205 theorems), one conjunctive frame per function over twelve fields.
3. (a): `Run_writes` on `exec_state s`, `data_bytes_exec` (with translation off the data bytes
   in `exec_state s` are those in `s`), `dataAddr_off`; the byte form by `pmpCheck_byte` and
   `pmpCheck_RW`; the physical form by `dataAddr_pmpCheck`.
4. (b): `fetch_bytes_off` and `pmpCheck_byte`; for the fault, `Fetch_fault` (the fetch result
   from `fetchAddr_off`, `rawReadInst_eq` and `fetchAddr_Skip`, unfolding only the outer
   `let`s of `Fetch` so that the `write'Delta` chains of the other branches are never
   expanded) and `Next_inst`.
5. (c): `Next_reads` writes the second state as the first with its memory replaced; the
   interrupt check by `checkInterrupts_CLINT`; then `Fetch_reads` and `Run_reads`, their side
   conditions from `step_reads`, `fetch_bytes_next_pre`, `data_bytes_exec`, `fetchAddr_off_MEM8`
   and `dataAddr_off_MEM8`; `next_post` and `cycle_step` by `same_except_inert`.
6. (d): `Run_U`, one lemma per instruction definition generated by one tactic (unfold, split
   the conditionals and cases, simplify with the frames, the FP lemmas `write'fcsr_MCSR`,

   Off; the reservation only by LR/SC; NextFetch none, a branch or a trap; a trap with the

   the four forms of a U-mode step, and `takeTrap_fields` says what a trap entry to M or S

7. Corollaries: `U_bare_intro`, `pmpCheck_words`, `pmpCheck_MCSR`, `pmp_legal_write_read`,

1. Classification (section 1 of `riscv_refineScript.sml`): two fixpoints over the call graph

### 4.11 The machine timer, as built

1. The clock: `same_except_set_mtime` and `tptick_same_except` from `same_except_upd`;
   `same_except_set_mtime_eq` and `set_mtime_id` by record and function extensionality, with no
   bit-blasting; `mtime_set_mtime` unfolds `mtime` to the eight bytes it reads and bit-blasts
   their concatenation; `mtimecmp_set_mtime` decides each of the eight address comparisons
   (`mtimecmp` of hart `h` against the bytes of `mtime`) by bit-blasting.
2. The tick-point execution: `tpexec_shift` and `tpexec_segment` by induction on the index;
   `tpexec_stopped` by induction, the strict guard `mtime () post <+ 0w` being false with no
   bit-blasting (a non-strict guard would need `set_mtime (mtime () s) s = s`).
3. The timer interrupt: `checkInterrupts_U_timer_pending` and `checkInterrupts_U_timer`
   unfold `checkInterrupts` with the step library's `read_mip_eval` (`mip` as a word), split the
   conditionals of `highestInterrupt` for the M and the S branch and bit-blast each case;
   `Next_U_timer` takes `Next_interrupt` (`Next_split` for an interrupt), the step library's
   `takeTrap_Machine` (the trap entry into M as one record update), `curPrivilege_User` for MPP,
   and the definitions of `next_pre` and `cycle_step`; `Next_M_no_interrupt` is
   `checkInterrupts_Machine` for the replaced memory.
4. The commutation: `CSRMap_noclint` by the cases of `CSRMap`, with the `_MEM8` lemmas of
   `riscv_footprintTheory` for `MCSR`, `read_xepc` and `raise'exception`; `writeCSR_noclint`
   and `accessCSR_noclint` from it; the six CSR instructions by one generated proof each;
   `Run_noclint` by the cases of the instruction. `Run_reads_M` splits on `noclint_inst`: an
   instruction that is one commutes with replacing the memory and writes none
   (`noclint_mem_access`, `Run_MEM8_frame`), and every other is `Run_reads`. `Next_reads_M`
   follows `Next_reads` (§4.8, 5) with the interrupt check of both states from
   `checkInterrupts_Machine` instead of `checkInterrupts_CLINT`.
5. The hardware execution: `noclock_step` is `Next_reads_M` with `D = mtime_byte`, after
   `same_except_set_mtime`, `same_except_sym` and `same_except_trans`; `texec_defer` by
   induction on the length of the segment; `texec_defer_read` by induction on the position `i`
   in the segment, with three cases: before the read the two executions agree but for `mtime`
   and the run has not changed `mtime` since its start (`noclock_step`); at the read the clock
   sets the bytes of `mtime` to those that the run has, so the two states are equal
   (`same_except_set_mtime_eq`, `set_mtime_id`); after it they agree but for `mtime` again.
6. The example: EVAL needs the definitions of the model in its compset, which L3's export does
   not add; outside the heap of `../step`, which HolBA does not build, the update and accessor
   theorems of the model's records are missing as well. The script adds the definitions of
   the functions that `Next` reaches (the closure of `Next_def` over the constants of
   `riscvTheory`: 320 definitions) and the update and accessor theorems of the model's types
   (`TypeBase.updates_of`, `TypeBase.accessors_of`: 258 theorems), with `computeLib.add_funs`,
   whose interface is the same in HOL4 `develop` and `trindemossen-2`. It does not add every
   definition of `riscvTheory`: with `trindemossen-2` they include the constructors of the
   enumerated types (`User = num2Privilege 0`, ...), with which EVAL did not prove
   `ex_timer_base_no_interrupt` in ten minutes.

## 5. Decisions

| # | Question | Choice | Reason |
|---|---|---|---|
| I1 | Structural proof or step evaluation | structural over the definitions (§4.1) | covers all instructions and interrupts, and `Next` itself |
| I2 | Read dependence: read set or two-state relation | two-state `same_except D`, with the read set as its side condition | composes along `Next`; tolerates over-approximated write sets |
| I3 | Exhaustiveness: script or theorem | both: the build asserts the syntactic classification, and `Run_writes`/`Run_reads` and the 186 lemmas prove it | the assertion catches a model change early; the theorems are what (a) and (c) use |
| I4 | Alignment of the physical address | none needed: `rawReadData_bytes` and `rawWriteData_bytes` hold at every alignment | the instruction lemmas then hold for any translation |
| I5 | Translated accesses | the instruction and fetch lemmas take `dataAddr`/`fetchAddr` agreement as a hypothesis, true when translation is off | translated U-mode is out of scope; the hypothesis isolates the PTE reads |
| I6 | CLINT | its bytes are a separate read set (`clint_byte`) | `mtime`/`mtimecmp`/`msip` are memory here ([D67]) and are read without a PMP check |
| I7 | Weakest privilege hypotheses | `effectivePrivilege () s = User` for data, `curPrivilege () s = User` for fetch and step legality | the model's own predicates; `U_bare_intro` gives the register-level form |
