# RISC-V L3 model: PMP isolation of U-mode steps

Theorems about the HOL4 RISC-V model of `../model` (`riscvTheory`, generated by L3 from
`../src/riscv.spec`) and nothing else: which memory a step of the model reads and writes, and,
in U-mode with address translation off, that the step respects the PMP configuration. The
design, the exact statements of the U-mode theorems and the proof plan are in `DESIGN.md`.

| File | Contents |
|---|---|
| `riscv_footprintScript.sml` | `riscv_footprintTheory`: the memory footprint of every function on the way from `Next` to memory (stage 1, built) |
| `DESIGN.md` | definitions, statements (a)-(d), the memory paths of the model, proof architecture, decisions |

Stage 2 (`riscv_isolationTheory`, not yet written) proves the U-mode theorems (a)-(d) of
`DESIGN.md` §2 from this theory.

## Building

    cd examples/l3-machine-code/riscv/isolation
    Holmake

It uses the heap `../step/riscv-heap` and builds `../model` and `../step` first if needed. With
`../step` built, the theory takes about 2 minutes and at most 2.1 GB of memory (single job). It
uses no `cheat`, axiom or oracle: every theorem carries only the `DISK_THM` tag of a loaded
theory.

## What `riscv_footprintTheory` proves

The PMP rules are those of the privileged spec, P §3.7 (p.70-74), as the model implements them
in `pmpCheck` (`../doc/design-privileged.md` chapter 5, D47-D62); address translation is
`translateAddr` (`../doc/design-smode.md` chapter 3).

**Which functions touch memory.** Of the 253 functions reachable from `Next` that involve the
state, the build computes the 67 whose definitions mention memory, directly or through a
callee, and fails if they are not the expected list (`DESIGN.md` §3.2). For each of the other
186, `f_MEM8` proves that `f` commutes with replacing the memory, so it neither reads nor
writes it (e.g. `dfn'ADD_MEM8`, `takeTrap_MEM8`, `mret_MEM8`, `write'CSRMap_MEM8`,
`pmpCheck_MEM8`); `f_MEM8_frame` that it leaves memory unchanged, and `f_procID` that it leaves
`procID` unchanged (for the 153 that return a state).

**Memory primitives, at every alignment.** `rawReadData_bytes`: the doubleword read at `a` is
the 8 bytes from `a`. `rawWriteData_bytes`, `rawWriteData_eq`: a write of `n` (1, 2, 4 or 8)
bytes at `a` sets the `n` bytes from `a` to the low bytes of the data and leaves every other
byte, including the rest of the doubleword(s) it rewrites, as it was; `rawWriteData_MEM8`,
`rawWriteData_frame` follow. `rawReadData_agree_1/2/4/8`: the part of a read that a load
keeps depends only on the bytes it loads. `write'MEM_bytes`, `rawReadInst_eq`.

**The PMP check of an access.** `dataAddr_pmpCheck`, `fetchAddr_pmpCheck`: whatever the
privilege and the translation, a physical address that `dataAddr` or `fetchAddr` approved
passed `pmpCheck` for its access (data: its width and kind, with the effective privilege of P
§3.1.6.4; fetch: the 2-byte parcel, execute, current privilege). `translateAddr_off`,
`dataAddr_off`, `fetchAddr_off`: with translation off (privilege M, or `satp_bare`) the
physical address is the virtual one and approval is exactly `pmpCheck`; `dataAddr_off_MEM8`,
`fetchAddr_off_MEM8`: and then they read no memory. `align_tests`: the instructions' alignment
tests are natural alignment.

**The CLINT.** `mtime`, `mtimecmp`, `msip` are words of memory in this model (D67), read
without a PMP check. `checkInterrupts_CLINT`, `read_mip_CLINT`, `CSRMap_CLINT` (the `time`,
`mip`, `sip` CSRs), `accessCSR_CLINT`, `writeCSR_CLINT`, `dfn'WFI_CLINT`: these depend on
memory only through the CLINT bytes of the hart (`clint_byte`).

**Every instruction that accesses memory.** The 37 instruction definitions that call
`dataAddr` (loads, stores, LR/SC, the 18 AMOs, FLW/FLD/FSW/FSD; the compressed forms decode to
the same instructions) are listed in `mem_access` with their access: virtual address, width,
PMP kind. For each, with no hypothesis on the privilege or `satp`:

- `<I>_writes` (stores, SC, AMOs, FSW, FSD): a byte the instruction changes is one of the bytes
  of its access, the access is aligned, and `dataAddr` approved its physical address
  (`data_bytes`), so `pmpCheck` held for a write.
- `<I>_MEM8_frame` (loads, LR, FLW, FLD): the instruction changes no memory.
- `<I>_reads`: two states equal except on a set `D` of bytes give results equal except on
  `D` (`same_except`), if `D` misses the bytes the instruction reads (its `data_bytes`, for
  loads, LR, AMOs, FLW, FLD; none for stores and SC) and `dataAddr` gives the same answer in
  both (it does when translation is off).

The CSR instructions and WFI have `<I>_MEM8_frame` and `<I>_reads` with the CLINT bytes as the
bytes read. `Run_writes`, `Run_reads`, `Run_MEM8_frame` are the same for every instruction at
once, so the list is exhaustive: an instruction not in `mem_access` changes no memory, and one
not in `mem_access` and not a CSR instruction or WFI (`clint_inst`) reads none.

**Fetch.** `Fetch_MEM8_frame`: fetching changes no memory. `Fetch_reads`: two states equal
except on `D` fetch the same instruction and stay equal except on `D`, if `D` misses the bytes
of the parcels that `fetchAddr` approved (`fetch_bytes`) and `fetchAddr` agrees.
`fetch_bytes_off`: with translation off those are the parcels at the pc and pc + 2 that
`pmpCheck` lets the current privilege execute. `fetchAddr_Skip`, `Fetch_MEM8`.

## Hypotheses

The theorems above have none beyond what each states. The U-mode theorems of stage 2 use:

| Hypothesis | Why |
|---|---|
| `effectivePrivilege () s = User` | loads and stores are checked with the effective privilege (P §3.1.6.4 p.35); with MPRV = 1 and MPP = M a U-mode store would be checked as M. In a reachable U-mode state MPRV = 0. |
| `curPrivilege () s = User` | fetches use the current privilege; it is what makes the step a U-mode step. |
| `satp_bare s` | translated U-mode is out of scope; only Sv39/Sv48/Sv57 turn translation on, so this is weaker than satp.MODE = 0. |
| the secret bytes are not CLINT bytes | the interrupt check and the `time` CSR read `mtime`, `mtimecmp`, `msip` from memory without a PMP check. |
| `checkInterrupts () s = NONE` (fetch fault only) | a step that takes an interrupt fetches nothing. |
| `c_NextFetch = NONE` (frames only) | an invariant between steps; a stale `SOME Mret` would make `Next` perform an MRET. |
